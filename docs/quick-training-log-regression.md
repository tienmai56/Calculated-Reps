# Quick training log UI regression checks

Database migration `20261105212524_quick_training_log.sql` is deployed to Mat Mind. The source and regression suite match the validated deployment.

## Automated checks

On macOS, build the mock and run the app tests with an installed iPhone simulator:

```sh
xcodebuild -scheme QuickTrainingLogMock -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO build
xcodebuild -scheme IntentionalTrainingNotes -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO test
```

`QuickLogTechniqueTests` covers latest-list persistence, empty lists, custom names, rep history, account isolation, failed saves and Undo. `TrainingCalendarTests` covers one-tap logging on planned and unplanned days, hits attached after a tap feeding technique charts, rhythm days from quick logs and started plans, private counter changes, attendance, publication with or without a photo, Completed labels, Undo, save failures, account clearing, seeded reset and rejection of unsupported live requests. Existing main tests also cover session photos, username following, notifications and the read-only Profile heatmap.

## Release boundary

- The complete quick-log UI is available in **QuickTrainingLogMock** without sign-in or network writes.
- Live quick logging enables when all feature snapshot fields are present; the deployed snapshot provides them. Refresh or restart the regular app to fetch the new snapshot.
- Training cards show the smaller right-aligned **Complete & Share** or **Completed**, with avatars and no going-count label. These styling changes use the current backend and existing composer.
- Run `sh scripts/test-database.sh` on the disposable local PostgreSQL container to validate the full chain, baseline authorization, quick logs, completion/Undo, photo saving after completion and username concurrency.

## Technique sheet

- **Log techniques** (after a tap) edits that log: counts start from its saved hits and save on every −/+. Stats' **Log hits** opens **What did you hit today?**: no log or count changes until Save log succeeds. Older-week taps and Log another session log immediately without a sheet. Neither sheet has a date heading, day picker, search or privacy helper. Its height fits the content. The add-technique **Add technique** button is secondary, so Done or Save log stays the main action.
- Start with Heel hook, Back take and Armbar at zero. Minus cannot go below zero; zero never removes a technique. Save log stays disabled until at least one technique has positive reps.
- Add technique opens a labeled plain name field; Cancel and Add technique sit outside it, with Cancel text aligned to the field’s leading edge. Blank and duplicate names are rejected. Arbitrary names and long names work. Canceling the form changes nothing.
- Edit → remove → Undo restores the technique’s position and draft count. Remove every technique, close and reopen: the list stays empty with Add technique available. Removing a technique never changes already saved logs.
- Close the sheet after adding/removing without saving reps: the latest list still appears next time. Repeat on an older date and relaunch the preview: latest edits win. Daily counts start fresh, and older-week entries display saved name/count snapshots.
- Save failure retains draft counts and offers retry without adding an entry. Undoing a saved log removes its rep details but keeps list edits. Switching accounts during a save cannot copy reps, list state, Undo or success feedback into the next account.
- **Storage boundary:** technique preferences and per-log rep details are stored on this device under each account, following Goals. They do not sync across devices. The preview uses a separate namespace. No SQL changes or backend deployment are included.
- Check a narrow phone, a long technique list, keyboard focus/scrolling, large Dynamic Type, VoiceOver control labels and Reduce Motion. The sheet grows as content is added and scrolls at the system height limit; scroll to Save log with the keyboard open.
